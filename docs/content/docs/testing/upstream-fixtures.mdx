# Upstream Fixtures

Pitmaster tests against fixtures from other git implementations and the official git test suite. These fixtures contain repositories with known structures, exercising edge cases and format variations that a single test suite might miss.

## Fixture sources

| Source | Fixture count | What it provides |
|--------|--------------|-----------------|
| libgit2 | 63 | C implementation test repos (complex trees, merge scenarios, submodules) |
| go-git | 46 | Go implementation test repos (pack files, protocol, various formats) |
| isomorphic-git | 71 | JavaScript implementation test repos (broad coverage, HTTP protocol) |
| dulwich | 6 | Python implementation test repos (pack edge cases) |
| JGit | 7 | Java/Eclipse implementation test repos (large packs, reftable) |
| git test suite | 393 | The canonical test suite from git/git (the ultimate authority) |

## Acquiring fixtures

Each fixture source has a dedicated acquisition script:

```bash
# All fixtures at once
./bin/acquire-fixtures

# Individual sources
./bin/acquire-go-git-fixtures
./bin/acquire-isomorphic-git-fixtures
./bin/acquire-dulwich-fixtures
./bin/acquire-jgit-fixtures
./bin/acquire-git-test-suite

# Git's own test suite (largest)
./bin/acquire-git-suite-fixtures
```

### libgit2 fixtures

```bash
# Clone and extract
git clone --depth=1 https://github.com/libgit2/libgit2.git /tmp/libgit2
```

libgit2's test fixtures use `.gitted` directories (renamed from `.git` to avoid nested repo issues). The acquisition script renames them back:

```bash
# In each fixture directory
mv .gitted .git
```

Fixture locations in the libgit2 source:
- `tests/resources/testrepo.git` (basic repo)
- `tests/resources/merge-resolve/` (merge scenarios)
- `tests/resources/submodules/` (submodule fixtures)
- `tests/resources/packfile/` (pack file edge cases)

### go-git fixtures

```bash
git clone --depth=1 https://github.com/go-git/go-git-fixtures.git /tmp/go-git-fixtures
```

go-git fixtures are tarballed `.git` directories. The acquisition script extracts them:

```bash
for tgz in /tmp/go-git-fixtures/data/*.tgz; do
    tar xzf "$tgz" -C "scenarios/upstream/go-git/$(basename "$tgz" .tgz)"
done
```

### isomorphic-git fixtures

```bash
git clone --depth=1 https://github.com/nicolo-ribaudo/isomorphic-git-fixtures.git /tmp/iso-git
```

isomorphic-git has the broadest collection of test repositories, covering HTTP protocol edge cases, shallow clones, and various ref formats.

### dulwich fixtures

```bash
./bin/acquire-dulwich-fixtures
```

dulwich (Python git implementation) provides focused fixtures for pack file parsing edge cases, including unusual delta chain configurations.

### JGit fixtures

```bash
./bin/acquire-jgit-fixtures
```

JGit (Java/Eclipse) fixtures include large pack files and reftable format examples.

### git test suite

```bash
./bin/acquire-git-suite-fixtures
```

The official git test suite from `github.com/git/git`. This is the largest source (393 test scripts) and the ultimate authority. The acquisition script:

1. Clones the git source
2. Runs selected test scripts in debug mode
3. Captures the resulting test repositories
4. Organizes them under `scenarios/upstream/git-suite/`

```bash
cd /tmp && git clone --depth=1 https://github.com/git/git.git
cd git/t && bash t1000-read-tree-m-3way.sh --debug
# Resulting repos are in test output directory
```

## How upstream fixtures are tested

Upstream fixtures are tested through the same oracle model as regular scenarios:

1. The `setup.sh` unpacks or links the fixture
2. `bin/oracle` captures git's view of the fixture
3. `bin/actual` captures Pitmaster's view of the same fixture
4. `bin/compare` diffs the outputs

```bash
# Run all upstream fixture scenarios
./bin/test-regression --category upstream

# Run fixtures from a specific source
./bin/test-regression --category upstream/libgit2
./bin/test-regression --category upstream/go-git
```

## What upstream fixtures catch

Upstream fixtures exercise edge cases that hand-written scenarios might miss:

- **Pack file variations**: unusual delta chain depths, mixed OFS/REF delta types, v1 pack indices
- **Tree sort order**: entries that expose sort order bugs (e.g., filenames like `a`, `a-`, `a/b`)
- **Ref format variations**: packed-refs with and without peeled values, reftable format
- **Index extensions**: TREE, REUC, EOIE, and IEOT extensions
- **Object encoding**: commits with unusual author formats, multi-byte UTF-8, GPG signatures
- **Submodules**: gitlink entries (mode 160000) and `.gitmodules` parsing
- **Empty objects**: empty blobs, empty trees, empty commit messages

## Support matrix

The `bin/support-matrix` command generates a compatibility report across all upstream sources:

```bash
./bin/support-matrix
```

Output shows which features are exercised by which fixture source and whether Pitmaster passes.

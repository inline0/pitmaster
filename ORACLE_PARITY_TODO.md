# Oracle Parity Backlog

This file exists to stop another “implemented, but not actually Git-proven” feature from being treated as done.

## Rule

No support-matrix row may be treated as truly `DONE` until all of the following are true:

1. Pitmaster mutates or reads real repository state in a Git-backed integration test under [`tests/Integration`](tests/Integration).
2. Stock `git` validates or observes the same state in that test.
3. At least one oracle scenario under [`scenarios`](scenarios) covers the feature family.
4. The relevant scenario passes via [`bin/test-scenario`](bin/test-scenario).
5. The scenario is included in recurring sweeps via [`bin/test-regression`](bin/test-regression) and [`bin/verify-compliance`](bin/verify-compliance).

If stock `git` is not the real oracle for a feature, that row must not be described as “oracle-verified against git”. It needs a different oracle and a different label.

## Evidence States

- `Mapped`: there is already Git-backed evidence plus an in-repo oracle scenario family to bind into compliance sweeps.
- `Weak`: there is some evidence, but the Git comparison, scenario coverage, or edge-state coverage is incomplete.
- `Claim correction`: the support matrix currently overstates the row; either the public feature is missing, only unit-tested, or not proven enough to justify `DONE`.
- `External oracle`: stock `git` is not a sufficient oracle for the row.

## Required Commands

- Single scenario: [`bin/test-scenario`](bin/test-scenario)
- Batch scenario sweep: [`bin/test-regression`](bin/test-regression)
- Compliance report: [`bin/verify-compliance`](bin/verify-compliance)
- Oracle harness entrypoints: [`tests/Oracle/ScenarioRunner.php`](tests/Oracle/ScenarioRunner.php), [`tests/Oracle/ScenarioComparator.php`](tests/Oracle/ScenarioComparator.php)
